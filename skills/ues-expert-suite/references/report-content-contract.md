# HTML 报告内容合同

本合同规定联合 HTML 报告必须回答的问题。视觉与交互继续服从 `visual-report-system.md` 和 `dashboard-report.md`。

## 输出范围

由总控编排的单项、任意子集和完整运行都使用同一个三标签HTML壳层。只渲染本次`executed`或`limited`专项的结果；`deferred`、`not_applicable`、`unavailable`与`not_selected`只在“范围与方法”的路由表说明，不生成空白总览卡或伪审计表。

## 总览：分数为什么是这个数

仅在满足计算条件时显示综合分；仅为本次已执行且有0–10分的易用性、任务、一致性或性能专项显示横卡。综合分卡不放展开明细，只给总分、结论、确认问题数和耗时。每个有分专项提供可展开的“查看得分明细”，采用固定三段式：

- 哪里没做好：只写确认的非满分来源；
- 怎样影响分数：用产品语言说明影响了理解、操作、完成、连续性或速度中的哪一项；必要时给一个扣分数字；
- 为什么得到当前分数：用一句话说明通过范围与问题范围的关系。

易用性、任务、一致性和性能都使用这三段。不要在总览展示 E/P/Q、J/n、内部权重、长公式或算法变量；这些字段保留在“范围与方法”的计分口径中。场景参考分只补一句“当前任务为何让该问题更重要”。

另外：

- 基础检查：没有数值分，只显示通过、失败、未验证、N/A及其含义。
- 虚拟用户：没有数值分，只显示实际角色、任务与运行状态。
- 视觉质量：总览不显示专项卡、0–100分、四轴或finding数量。只跑视觉时，总览显示本次范围与一句话结论，并提供进入“范围与方法”的页内跳转。

分数明细不得用“详见 JSON”代替。一个确认问题命中多个专项时，各专项分别说明它如何影响本专项分数；没有影响时明确写“不参与该专项扣分”。

## 整改优先级：确认需要改什么

只放 confirmed 问题和合法的不计分建议。每个问题展示事实、影响、整改、验收、证据、来源准则，以及它对各专项分数的实际影响。rejected、pending 和 blocked 候选不计入整改数量。

## 范围与方法：测了什么，排除了什么

保留范围、任务轨迹、性能合同和完整准则表。另加“已排除的候选判断”折叠块。每个 rejected 候选必须展示：

1. 初始假设及潜在后果；
2. 为区分真假执行的验证动作；
3. 实际观察到的反证或合理替代解释；
4. 排除结论；
5. 尚未覆盖的条件。

只有这个块完整生成时，总览或范围卡才允许显示被排除数量。结果未保存上述字段时，隐藏数量并写“本次未形成可展示的排除记录”。pending/blocked 候选单列为待补证，不计入排除。

视觉质量被执行或受限执行时，增加`data-ues-visual-quality`一级折叠块。完整显示整体判断、可选实验分、四轴、单元范围、冻结信息、finding disposition、strengths、resolved suspicions、needs_evidence、静态边界与真实产物链接。视觉专项没有固定准则库，不生成pass/fail准则行。完整规则见`visual-quality-integration.md`。

## 数字显示规则

- 显示数字就同时提供定义、分母或口径和下钻明细。
- 覆盖数写成“已判断 18 / 22”，不要只写“18”。
- “候选 3”必须拆成确认、排除、待补证；没有逐项内容时不要显示候选总数。
- 未验证项不会扣分时，紧邻数字说明“不等于通过，也未作为0分”。
- 四舍五入后的展示分与内部计算分并存时，公式显示内部精度并注明最终保留位数。

## 模板插槽与机器标记

`report-shell.html` 中下列标记按已执行范围保留并填充：

- `data-ues-score-breakdown="ease|task|consistency|performance"`：对应专项有数值分时必需；
- `data-ues-confirmed-issues`
- `data-ues-rejected-candidates`（仅有完整排除记录时）
- `data-ues-audit="baseline|ease|consistency|task|performance"`：对应专项executed/limited时必需；
- `data-ues-visual-quality`：视觉专项executed/limited时必需，且必须位于`#method`内、不得位于`#overview`。

这些标记用于 `validate_html_report.mjs` 按`assessment.json`中的实际范围检查报告完整性。总览不得出现 `data-ues-score-breakdown="overall"`、视觉质量专属组件、排除数量或无真实数据的历史趋势占位。允许增加有数据的内容，不得删除既有三标签、已执行专项得分明细、整改工作台、排除记录和实际适用的审计插槽。
