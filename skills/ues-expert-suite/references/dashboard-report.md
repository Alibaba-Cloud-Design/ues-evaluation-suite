# UES 看板式报告

本版参考用户提供的 UES 看板截图，更新呈现方式，不采用截图中的业务数据、评级阈值、人员、公式或水印。全局证据、术语和完整准则要求仍遵守同目录 `visual-report-system.md`。这里的外观与明细布局优先于旧版圆角大卡片布局。

## 综合与单项共用

- 综合报告：蓝色通栏页头；首行综合分卡与维度概览；下方按已执行的易用性、任务、一致性、性能排列横向摘要；基础检查独立显示问题与覆盖，虚拟用户单独显示覆盖与结果。视觉质量不在总览放卡，完整内容进入“范围与方法”。每个专项用自己的名称、日期、口径、来源和评级，不共用一套评级阈值。
- 单项报告：同风格蓝色装饰页头；有合法总览分/状态的专项，第一行左侧显示大分数/状态和标尺，右侧显示结论及关键指标；下一块放可筛选问题表、任务表或测量明细；范围与方法保留完整准则、计算和证据边界。视觉质量单项是例外：总览只显示范围与跳转，完整结果位于“范围与方法”。
- 保留总览、整改优先级、范围与方法三个内容入口及全部已有内容。总览可放任务明细、问题摘要及dual模式的场景影响卡；完整问题集中在整改优先级，点击表格内“证据与验收”就地展开事实、影响、建议、验收与证据，不要求读者去另一页匹配截图。只有场景内容形成独立阅读任务且会明显破坏总览层级时才增加“场景影响”入口，原三个入口不得删除、合并或改名。
- 使用本技能 `assets/report-kit/` 中的模板、样式和脚本。`dashboard-example.html` 是标明虚构数据的组件示例，不是评估结果；实际报告必须替换所有示例内容。对联合报告与单项报告均可内联CSS/JS，离线打开。

## 分数与数据

- 大分数带正式名称、满分、来源和评级。分段标尺的分界点读取当前专项的评分模型；不从截图照抄。未知阈值时只画0–10连续标尺且不附分档色区。
- 综合分严格按现行公式和可计算条件产生，基线不入数值加权；正式/简易名称遵守总入口。不得自行给综合分赋“卓越”等未定义评级。
- 历史趋势和“较上期”仅在存在同口径、可比较的真实记录时显示；否则显示“首次评估 / 无可比历史”，不画装饰折线。有历史时注明期数、日期、口径变化，不跨版本硬接趋势。
- 解决率、平均解决时长、处理人需要真实跟踪数据；本次发现的问题默认状态为“未跟踪”，不默认已解决或待处理。已取消不自动算已修复，已发布未经复验不能声称问题已消失。缺少跟踪数据时省略这些运营指标。
- 任务简易模式用自己的场景指标，不能借布局把它写成真实用户完成率/相对效率。性能保留正式PCP/合成PCP/普通网页测量的区别和数据合同。
- 满意度不属于现有专项。只有用户提供合法调查结果和口径时作为补充展示，不参与当前综合分，不从专家评分推算；否则不展示该卡。
- 未评分写明原因，基线和虚拟用户不画数值标尺。雷达图可选，维度需同尺度，缺失值不补零；精确横条始终可用。

## 组件和交互

使用 `.ues-board-row` 包含 `.ues-score-block` 与 `.ues-board-content`；结论用 `.ues-summary`，关键指标用 `.ues-metrics` 和 `.ues-metric`。所有CSS变量沿用 `ues-report.css`。

明细表放入 `data-ues-filter-table` 容器，搜索框标记 `data-ues-search`，状态与优先级下拉框分别标记 `data-ues-filter="status"`、`data-ues-filter="priority"`；数据行使用 `data-ues-row`，并提供对应 `data-status`、`data-priority`。`data-ues-filter-count` 显示筛选结果数，`data-ues-empty` 显示空结果。搜索与筛选交集生效，不改变总问题数。问题证据使用原图灯箱。无实际链接或动作的“发起、录入、查看、导出”按钮不得复制。

## 验证

检查1440px与390px、系统浅色与深色偏好下均保持报告浅色；表格在容器内横滚而非撑宽页面。检查标签键盘导航、搜索与筛选交集、空结果、展开证据、灯箱退出。核对数字与已校验结果一致；只改呈现时不重算或改动评分算法。

## 固定浅色与页头插画

页面、表格、表单固定浅色，系统暗色偏好不得覆盖。综合与单项报告均复用 `ues-banner-art.png`，参考扇形白色报告卡、蓝色卡头、悬浮玻璃圆环、底部波浪。图案属于装饰，使用用户提供原图；原图中的8.7是固定装饰内容，不是当前报告分数，不得读取或用于计分。真实分数保留在HTML正文。移动端图案移到文字下方，避免遮挡。离线交付需复制PNG；单文件报告须把CSS中的PNG URL替换为data URI。

## 首页布局与卡片配色

首行左侧为综合分和趋势/无历史状态，右侧独立子指标概览。易用性、任务、一致性用通栏横卡；性能及基线/覆盖等较小模块按实际内容双列。没有满意度调查时不为凑布局创建满意度。仅综合分块按实际分数档位有浅色渐变，其余卡片与分数区为白色，结论浅蓝紫底、指标浅灰底；评级颜色仅作用于标签及标尺，不能把所有卡染成绿色。Banner使用随包原始PNG，保留文件不裁切，通过CSS定位适配透明边距。

## 综合分底色分档

用户指定的综合分视觉分档：8.5≤分数≤10 为浅绿；7≤分数<8.5 为浅蓝；5≤分数<7 为浅橘；0≤分数<5 为浅红。未评分、缺失或非法值使用中性白底，不当作0分。使用与大数字一致的最终展示分作为档位输入，避免显示8.5却仍是蓝底。此分档只控制综合分卡底色，不新增评级、不更改专项分数和评级阈值；专项卡片仍保持白色，独立基础风险与覆盖状态始终可见。

综合分卡设置 `data-ues-overall-score="8.3"`，共享初始化脚本设置 `data-score-tone`；静态报告可预设相应色名。合法值范围0–10。当前8.3示例为浅蓝。数值与口径文字仍必须显示，颜色不替代结论。

## 分数组件精细合同

标题左对齐，旁边提供可键盘展开的计分说明；右上角显示真实评估日期和可选期次。大分数旁紧跟本专项真实评级标签；不要把“/10”或示例口径塞进主数字行。口径和限制放底部辅助行，综合分无定义评级时不套用专项评级。

标尺不是进度条：灰色底轨覆盖0–10，仅当前档位整段着色，底部同色上三角按实际分数/10定位。刻度按实际数值比例排列，显示所有档位边界，分界有细分隔线。例：易用性8.2，高亮7–8.5，指针在82%；任务7.6，高亮6–8，指针76%；一致性9.0，高亮9–10，指针90%。每个专项从其现行评分模型读取阈值与评级，不能共用综合分阈值；一致性保留“历史参考档位”，简易任务保留模式限制。当前模板边界分别为综合/易用/性能0、5、7、8.5、10，任务0、5、6、8、10，一致性0、7、8、9、10，生成时须核对当前版本。

历史有效时在分数下展示较上期增减与单位，右侧可画真实样本微型趋势；持平明确为持平，不使用上升箭头。没有历史时显示首次评估，不伪造0增量或装饰折线。日期、期次、历史均读取结果元数据。底色只作用于综合分并遵守分档；专项保持白底，颜色集中在评级、所属色带与指针。

## 基线与虚拟用户独立卡片

基线与虚拟用户是两个独立专项，分别用与评分维度相同的 `ues-board-row` 横卡，不合并在一个“基线与角色覆盖”容器内。左侧标题、日期、主结果、覆盖条与口径；右侧浅蓝结论、浅灰指标和可展开明细。基础检查主结果显示发现问题/未发现问题和验证完整性，覆盖条表达判断数量；虚拟用户主结果可显示角色数和运行类型，覆盖条表达运行状态。这些数量不是评分，不画0–10分数标尺，不进入综合分。保留模拟与真实运行区分。已提供完整虚构案例，明细与当前卡片就地绑定。

## 摘要指标统一与简易性能精简

易用性、一致性、简易任务分右侧摘要下，统一显示“通过 / 失败 / N/A”三个数量块。数量从逐条判断统计，不从分数反推；部分通过、证据不足若非零须追加独立数量说明，不并入通过、失败或N/A。任务按任务×准则统计，明确任务数和判断总数，不把多个任务压成一套20条。任务表、比较组、原始分和风险上限等细节移入展开区或范围与方法，仍应可追溯。

简易性能分首页不显示右侧蓝色摘要及“数据来源 / 样本 / 误差”三块，保留左侧分数、评级和简易口径；来源、完成规则、样本、误差、测量证据与公式保留在范围与方法，不因首页精简而删除。正式性能按自身结果展示，不套用此精简规则。

## 简易性能与基线并排

综合报告中两者均存在时，将简易性能和基础体验与风险检查作为独立卡片放入 `.ues-performance-baseline-pair` 同一行，左右等宽；900px及以下自动上下排列。基线在半宽卡内采用上方主结果、下方摘要/数量/明细；简易性能标尺使用卡片可用宽度。虚拟用户继续独立通栏，不合并入基线。缺少其中一项时不留空槽，独立展示现有项。

## v0.3 独立检查展示

当前日常检查以“基础体验与风险检查”命名，禁止出现笼统的“基线不通过”主结论。逐条pass/fail/not_verified/N/A保留，not_verified中文为“未验证”，范围外另列，绝不并入失败。全局findings_status和verification_status分开显示；如无事前发布规则，发布状态为“未评估”，不作发布许可推断。

无障碍归入基础体验与风险检查BL-04，可展开细项；不生成独立分数、卡片或专项。

明细信息层级与折叠规则以 [visual-report-system.md](visual-report-system.md) 的“渐进展开与明细布局（v0.3.2）”为准；新报告使用同版 detail-layout 资源。
