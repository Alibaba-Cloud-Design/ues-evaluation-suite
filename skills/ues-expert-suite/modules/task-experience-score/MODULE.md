# 任务分专家

提供两套明确分开的结果：

- **AEM任务体验分**：使用真实用户完成率、相对耗时效率和冻结复杂度，按官方公式计算。
- **简易任务分**：产品未接入AEM时，根据非图片材料生成或读取任务链，通过场景测试、路径效率和20条任务准则形成0–10分、评级、卡点与建议。

报告必须写明使用哪一种算法。简易任务分不是AEM用户行为分，不得直接混入AEM产品平均值或冒充真实用户完成率。

## 联合运行接口

独立运行继续使用本专项现有合同。由 `ues-expert-suite` 编排时，读取总控冻结的任务合同版本、输入/画像/路由版本和共享 `evidence-index.json`，复用任务、场景、步骤、截图、交互、日志与终态证据ID。总控中的任务候选不等于本专项已确认；只有run-state记录confirmed且指向冻结合同后才能正式测试和计分。完整任务成功仍按success truth独立核验，共享摘要不能代替终态证据。新证据写专项fragment，由总控合并；任务或证据版本变化时先标stale并重做受影响场景和计分，不改变20条或AEM/简易公式。

同时读取 `diagnosis.json` 的任务决策合同、候选状态与反证记录。confirmed候选可提示任务断点，但不自动改变任务真值或分数；rejected候选用于避免重复误报，pending/blocked只能进入限制说明。已有入口、动作、反馈和终态证据满足本专项要求时复用，只补任务终点、边界或恢复缺口。

## 输入与证据等级

支持以下非图片输入：

| 输入 | 能力 | 结果名称 |
|---|---|---|
| 可运行HTML或网页URL | 实际执行正常、边界和恢复场景 | 简易任务实测 |
| 有序事件日志、操作录像文字稿或步骤—状态记录 | 重建已发生路径并核对结果 | 日志简易任务评估 |
| PRD、SOP、原型说明或结构化任务步骤 | 评价设计意图与可完成性 | 方案级简易任务评估 |
| 零散产品文字说明 | 可先生成任务合同；证据不足时只输出待验证方案 | 简易任务待验证 |

图片可以作为补充证据，但不能作为本模式的唯一输入。无顺序图片不得用于生成完整任务链或正式评级。

## 任务链来源

### 用户设置任务

保留用户给出的角色、目标、入口、前置条件、成功终点和步骤。只修正明显的格式问题；需要改变任务含义时先说明。即使任务链由用户提供，也要将规范化后的版本回显给用户确认，防止Agent误解或擅自补全。

### Agent自动生成任务

用户未设置任务链时，从材料中识别1–3个核心任务，并为每个任务生成：

```text
角色 → 目标 → 真实入口 → 前置条件 → 必要步骤 → 系统反馈 → 成功真值 → 结果去向
```

同时列出推断依据和不确定项。若多个解释同样合理，给出推荐版本与关键备选，等待用户选择或修改，不得自行选定后直接评分。

### 任务链确认门

Agent生成或规范化任务链后，必须暂停并请求用户确认。确认内容至少包括：

```text
任务名称 / 角色 / 目标 / 入口 / 前置条件
按顺序排列的必要步骤与关键系统反馈
成功真值 / 结果去向 / 评估范围 / 高风险动作
Agent推断项与仍待确认项
```

- 用户回复“确认”“按此评估”或等价表达后，才可生成测试场景、逐步检查准则和计算分数。
- 用户修改任一影响范围、步骤或成功真值的内容时，更新任务链并再次请求确认。
- 1–3个任务可在同一张确认表中一次确认，不要逐字段反复打断。
- 用户在最初请求中明确说“无需确认，按Agent识别结果直接评分”时，视为预先确认；仍须在报告中展示采用的任务链。
- 用户未确认时，只输出“等待任务链确认”，不能给出暂定分、预测分或评级。

## 简易任务分流程

1. **起草任务合同**：明确角色、对象、入口、成功真值、范围和风险。
2. **取得用户确认**：回显任务链与推断项；未确认就在此暂停。确认后将任务合同冻结。
3. **生成场景矩阵**：至少包含正常路径、一个适用边界、一个恢复/中断场景；高风险任务增加权限或确认场景。场景及权重必须在测试前冻结。
4. **建立步骤表**：每步记录用户目标、动作、所需信息、系统反馈、预期结果、实际/设计结果和证据。
5. **逐步检查准则**：把20条准则路由到相关步骤；同一准则命中多步时保留每个实例，任务级判断取最差实例，不通过重复命中稀释问题。
6. **计算代理指标**：计算可完成性率 `E_lite`、路径效率 `P_lite`、准则质量 `Q` 和覆盖率。
7. **执行确定性计分**：优先运行 `node scripts/calculate_lite_task_score.mjs --input-json <path>`；输入中的 `task.confirmed` 必须为 `true`。
8. **应用风险和证据上限**：先算原始分，再应用Gate/Major与输入证据上限。
9. **输出卡点与建议**：将失败步骤、直接原因、用户后果、相关准则和可执行修改合并成问题。

## 判断与问题合并

每条准则使用：`pass`、`partial_pass`、`fail`、`insufficient_evidence`、`not_applicable`。

- `pass` 也需要可定位依据。
- 未说明动态结果、外部真值或边界状态时记 `insufficient_evidence`，不能默认通过。
- 同一直接原因、同一对象、同一后果且可由同一修改解决的发现合并为一个卡点。
- 同一准则在不同关键步骤分别失败且需不同修改时保持为独立实例；任务级 `Q` 只取最差判断一次，避免重复扣分。
- 必要的安全确认、权限校验和高风险提示不能仅因增加步骤而判为冗余。

严重度由准则重要性与判断确定：

| 重要性 | fail | partial_pass |
|:---:|:---:|:---:|
| 3 | Gate | Major |
| 2 | Major | Minor |
| 1 | Minor | Advisory |

## AEM模式

已有AEM或等价行为数据时，按 `scoring-model.md` 计算 `E`、`P`、复杂度、`X`、`P'` 和 `S`。不要把简易模式的 `E_lite`、`P_lite` 或 `Q` 代入AEM公式。

可以在AEM分旁附加20条任务准则诊断，用于解释低完成率和低效率；这些诊断不直接修改AEM数值分。

## 简易模式输出

### 1. 结论

- 结果名称和证据等级；
- 原始分、风险上限、证据上限和最终分；
- 差 / 中 / 优 / 卓越评级，或因覆盖不足未评分；
- 一句话核心结论。

### 2. 自动识别或用户设置的任务链

列出角色、目标、入口、前置条件、步骤、成功真值与推断项，并注明任务链的确认状态及用户确认依据。

### 3. 计算链

展示：

```text
E_lite、场景覆盖
P_lite、效率依据
Q、准则覆盖
S_raw = 10 × (0.50E_lite + 0.20P_lite + 0.30Q)
风险上限 / 证据上限
S_final
```

### 4. 任务卡点

按Gate、Major、Minor、Advisory排序。每项包含失败步骤、证据、直接原因、用户后果、准则ID和是否影响完成。可在界面中定位的卡点默认附未改动原始截图和红框编号标注视图；报告先展示标注视图，并允许隐藏标注或查看原图。红框编号与卡点ID／问题序号一致，多区域使用A/B后缀。

### 5. 优化建议

建议必须指出修改对象、位置或流程节点、具体动作和预期改善；避免“优化体验”“减少步骤”等空话。优先解决Gate和影响多个场景的共同根因。

### 6. 逐步与逐准则明细

保留所有步骤、场景、20条适用准则、判断、置信度、证据与未验证项。`not_applicable` 和 `insufficient_evidence` 不得隐藏。

### 截图证据呈现

- 原始截图保持未改动；红框作为独立衍生图或可关闭覆盖层，仅用于定位问题，不产生新的任务事实。
- 标注应保留任务对象、失败步骤和必要上下文，不遮挡关键文案，也不把多个不同步骤强行框成一个问题。
- 同一截图支持多个卡点时，每个卡点必须有独立标注位置；切换卡点时同步切换截图、红框、证据ID、步骤和图注。
- 动态失败、等待时间、先后顺序和恢复是否成功不能只靠静态红框证明，必须同时引用有序状态、日志、时间戳或录像。
- 无法可靠定位或问题只存在于行为数据／计算结果中时，不画猜测框；说明截图不可得并给出可复核的非视觉证据。

生成可视化报告时读取 [references/visual-report.md](references/visual-report.md)。使用 UES 统一三标签壳层、任务卡、问题卡和证据灯箱；任务路径作为本专项内容插槽，不另建独立视觉系统。

## 边界

- 简易完成率是对冻结场景的可完成性代理，不是线上真实用户完成率。
- 方案级文本只能评价设计意图，最高7.9分，不能评为卓越。
- 覆盖不足时输出“未评分”和补证清单，不用未知项补满分。
- 不替代完整易用性、无障碍、安全、视觉质量或设计系统审计。
- 不修改线上数据、埋点、权限或生产状态，除非用户另行明确授权。

## 逐条证据验收

出分前读取 [references/evidence-validation.md](references/evidence-validation.md)，按当前评分输入校验证据引用；缺口不得用通用范围字符串或重复的笼统说明补齐。校验通过只证明引用与比较结构，不证明判断正确。旧报告可检查并保留缺口，不能倒填未执行的观察。
