# 任务分与易用性规则归属

本参考用于防止“任务分专家”与“易用性专家”重复检查、重复扣分。来源是 125 条 UX 规则清单的原文维度标签，以及任务评审导出的 3 条任务独有候选项。

## 结论

- 125 条中有 21 条带“任务”或“任务（条件触发）”标签。
- 18 条同时带易用性标签，是任务分与易用性的共享准则。任务分专家单独运行时必须检查；易用性专家已有可复用判断时直接继承，不重复检查或重复形成问题。
- 3 条仅标“任务”：`F1.05`、`F1.06`、`F2.04`。
- `F1.06` 的评审记录含“看下有没有其他类似检查项，可以删掉”的建议；结合当前套件决策，将其视为废弃候选，不作为独立条目。
- 因此任务分专家单独运行时共检查 20 条有效准则：18 条共享准则，加 `F1.05` 与 `F2.04` 两条独有准则。AEM模式中这些准则不修改官方数值公式；简易模式中按 `lite-scoring-model.md` 形成质量分 `Q`。

## F1.05 结果完整兑现用户输入和选择

### 命题

冻结的全部有效输入、选择、配置、对象、范围、顺序和权限均进入最终结果，并由独立真值逐项核对；未发现静默丢失、替换或错配。

### 判断标尺

- `pass`：全部有效输入和关键选择进入最终结果，并由独立真值核对一致。
- `partial_pass`：全部关键选择兑现，但至少一个非关键选择存在可定位偏差；不改变对象、金额、权限、范围或核心结果。
- `fail`：任一关键输入或选择未兑现、被静默替换，或最终对象、金额、权限、范围与确认不一致。
- `insufficient_evidence`：缺少运行路径、终态或独立真值；不得根据 UI 成功提示判通过。

### 证据

使用输入—确认—结果对照表，记录状态和转换，并附请求、持久化数据、队列或外部结果等独立真值。截图序列只能作为流程意图，不能正式证明外部结果。

## F2.04 无无效往返、重复录入和重复确认

### 命题

已知信息在全部适用步骤中被复用，未发现不推进任务的返回、重录、重选、重复确认或随即撤销。

### 判断标尺

- `pass`：已知信息被复用，路径无不推进目标的冗余动作。
- `partial_pass`：存在一至两个可定位的低风险冗余动作，但不形成循环且不改变结果。
- `fail`：出现循环、系统已知关键信息被反复索取，或重复动作导致失败、错误结果或显著阻断。
- `insufficient_evidence`：缺少有序步骤、动作或状态关系，无法判断是否为真实往返。

### 证据

使用有序事件或实测路径记录 `状态 → 动作 → 下一状态`，标出每一步是否推进目标、是否重复系统已知信息、是否源于必要安全确认。必要确认不能仅因步骤多而判成冗余。

## F1.06 的处理

`F1.06 界面完成状态与真实结果一致` 与易用性终态反馈、结果正确性核对存在明显重叠。当前任务分专家：

- 不把它列入独有诊断条目；
- 不单独形成问题或扣分；
- UI 成功/失败表达归易用性 `F3.05`；
- UI 与独立真值不一致造成的结果风险归 `F1.05`；
- 若未来正式规则库明确恢复该条，再按新版本更新本交叉表。

## 双 skill 同时运行

1. 任务分专家单独运行时检查20条任务准则；易用性专家单独运行时按其准则库检查。
2. 两个skill同时运行时，共享的18条以先完成且证据等级足够的判断为单一事实源；任务分专家只补 `F1.05`、`F2.04` 和缺失实例。
3. 同一证据若同时触发两边，只保留一个直接根因问题，不重复扣分。
4. AEM模式并列展示“行为任务分”和准则诊断，不把两套尺度算术平均；简易模式按固定算法将20条汇总为 `Q`。
