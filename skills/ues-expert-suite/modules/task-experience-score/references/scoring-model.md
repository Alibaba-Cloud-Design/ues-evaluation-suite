# 任务体验评分模型

本参考固化当前 skill 使用的任务分计算口径。来源为用户提供的[《体验度量_任务指标和算法说明》](https://yunzhidao.alibaba-inc.com/doc/toutiao/detail/56771)（2024-06-24）及 FY25“任务效率”评分截图。若后续官方口径更新，优先使用用户明确提供的新版并标注版本。

## 1. 变量与样本

### 任务完成率 E

`E = 任务成功提交用户数 / 访问任务页面的全部用户数`

- 分子：访问任务页面的样本中，最终提交成功的去重用户数。
- 分母：访问任务页面的去重用户总数。
- 范围：`0 ≤ E ≤ 1`。
- 成功必须绑定任务的真实终点或独立真值，不能只依据按钮点击或 UI 成功文案。

### 任务完成相对效率 P

`P = 理论完成耗时 / 实际完成耗时`

- 理论完成耗时：成功样本中，耗时较短的前 5% 用户耗时的中位数。
- 实际完成耗时：全部成功样本耗时的中位数。
- 范围：`0 ≤ P ≤ 1`。
- `P` 只基于成功样本。最快 5% 的取整、最小样本和异常值规则由组织数据口径决定；来源未明确时不得自创唯一答案。

### 任务复杂度与预期完成率 s

首次配置或新评估周期时，按用户操作步骤中位数分组：

| 组别 | 操作步骤中位数 | 预期完成率 `s` |
|---|---:|---:|
| A 简单 | `< 10` | `0.72` |
| B 中等 | `10–30`，含边界 | `0.53` |
| C 复杂 | `> 30` | `0.43` |

同一评估周期（财年）内，链路复杂度组别保持冻结；优化导致步骤变化时不在周期中途重分组。新周期或新增链路才按当前标准配置。

## 2. 相对完成率 X

把不同复杂度任务的完成率映射到统一尺度：

```text
E > s:  X = 0.5 + 0.5 × (E - s) / (1 - s)
E = s:  X = 0.5
E < s:  X = 0.5 × E / s
```

因此 `E=0 → X=0`，`E=s → X=0.5`，`E=1 → X=1`。

## 3. 效率变换 P'

为了提高效率分布的区分度：

```text
P' = LOG(P × 100 + 1, 101)
```

等价为：

```text
P' = ln(P × 100 + 1) / ln(101)
```

因此 `P=0 → P'=0`，`P=1 → P'=1`。

## 4. 单任务体验评分 S

```text
S = 10 × (P' × E + X) / (1 + E)
```

其中 `E`、`P`、`X` 均在 `[0,1]`，最终 `S` 在 `[0,10]`。

该式使效率权重随完成率提高：当 `E=0` 时，效率样本没有解释力，`S=0`；当 `E=1` 时，`X` 与 `P'` 各占一半。

计算时保留全精度。单任务展示通常保留一位小数；产品平均必须先使用未四舍五入的单任务分求均值，再进行最终显示舍入。

## 5. 评级

当前 skill 按 FY25 任务效率截图采用：

| 分数区间 | 评级 |
|---|---|
| `[0, 5)` | 差 |
| `[5, 6)` | 中 |
| `[6, 8)` | 优 |
| `[8, 10]` | 卓越 |

边界按左闭右开执行，10 分包含在“卓越”内。若其他文档仍使用“差 / 中 / 良 / 优”等旧文案，不要混用；报告中写明采用的评级版本。

## 6. 产品任务体验评分

从产品内选取 5–10 条任务链路，分别计算单任务体验评分后取算术平均：

```text
产品任务体验评分 = Σ 单任务体验评分 / 任务数
```

默认不做任务权重。若用户要求按流量、价值或风险加权，必须把它标成“自定义加权分析”，同时保留官方等权平均结果。

## 7. 数据校验

正式输出前至少检查：

- 分子、分母和去重口径一致，且 `0 ≤ 成功用户数 ≤ 全部用户数`；
- `E`、`P` 的单位明确，百分数已转换为小数；
- 理论耗时不大于实际耗时，时间戳无负数、跨会话或明显埋点断裂；
- `P` 只来自成功样本，失败样本只影响 `E`；
- 复杂度组别使用当前周期冻结值，而非优化后的临时步骤数；
- 比较两个周期或两个产品时，任务合同、窗口、用户结构与版本差异已经披露；
- 样本不足、最快 5% 只有极少观测或关键埋点缺失时，标记低置信或待测量，不把公式输出包装成稳定结论。

## 8. 解释边界

任务分是行为结果指标，不是纯界面评分。性能、服务故障、权限、用户结构、流量来源、数据质量和埋点质量都可能影响 `E` 与 `P`。解释低分时应把“测量问题、系统问题、流程设计问题、用户结构变化”分开验证。
