# 非AEM简易任务分算法

本算法用于没有AEM真实用户数据的产品。它从非图片材料中识别或接收任务链，执行或审查冻结场景，产生可完成性、路径效率和准则质量三个代理指标。

简易任务分用于早期评审、方案比较和问题定位，不得与AEM任务体验分直接横向比较。

## 1. 任务合同

每个待评任务先冻结以下字段：

- `actor`：执行角色；
- `goal`：用户希望达成的业务结果；
- `entry`：真实入口；
- `preconditions`：权限、数据、对象和环境；
- `success_truth`：证明任务真正成功的终态或独立真值；
- `steps`：必要步骤及每步预期反馈；
- `risks`：付费、删除、权限、生产、隐私、外发或不可逆影响。

Agent自动识别时，任务必须是“用户目标”，不能把页面、按钮或单个接口当作任务。若材料只能支持候选任务，应标记 `inferred` 并列出依据。

### 1.1 用户确认门

任务合同在用户确认前只是草案。Agent必须先回显完整任务链、推断项和不确定项并暂停；用户确认或修改后，才将任务合同冻结并进入场景生成、准则判断和计分。

确定性脚本要求 `task.confirmed=true`。缺少确认时不得输出分数或评级。用户最初明确授权“无需确认、直接按Agent识别结果评分”可记为预先确认，但仍需保存采用的任务链作为评分依据。

## 2. 场景矩阵

每个任务至少生成：

1. 正常核心路径；
2. 一个适用边界场景，如空数据、无效输入、权限不足或部分成功；
3. 一个恢复/中断场景，如取消、重试、返回、刷新或超时。

高风险任务增加权限、确认或撤回场景。不存在某类场景时说明 `not_applicable`，不要虚构。

场景在评估前设定重要性：

- `3`：核心正常路径或高风险结果；
- `2`：重要分支、权限或常见边界；
- `1`：低频边界或辅助恢复。

场景结果值：

| 判断 | 值 `o` | 定义 |
|---|---:|---|
| pass | 1 | 到达正确终态，关键输入、对象、范围和结果正确 |
| partial_pass | 0.5 | 到达正确终态，但存在可恢复的非关键偏差 |
| fail | 0 | 无法到达终态，或关键对象、范围、权限、金额、结果错误 |
| insufficient_evidence | 不进入分子分母 | 无法确认真实或设计结果 |
| not_applicable | 排除 | 场景不适用 |

关键结果错误不能评为 `partial_pass`。

## 3. 简易可完成性率 E_lite

对已经判断的适用场景：

```text
E_lite = Σ(场景重要性 a_j × 场景结果 o_j) / Σ(a_j)
```

另计算场景覆盖：

```text
C_scenario = 已判断适用场景权重 / 全部适用或证据不足场景权重
```

`E_lite` 是冻结场景的可完成性代理。方案级文本中的 `pass` 只表示设计方案支持该场景，不代表真实用户已经完成。

## 4. 简易路径效率 P_lite

### 4.1 以操作量为默认依据

对每个成功或部分成功场景：

```text
p_j = 必要用户动作数 / 实际或设计用户动作数
```

并限制到 `[0,1]`。必要动作必须能由业务依赖、安全、权限或风险控制解释；重复输入、无效返回、随即撤销和不推进目标的确认不计为必要动作。

多个可计场景时：

```text
P_lite = Σ(a_j × p_j) / Σ(a_j)
```

只对成功或部分成功场景计算，与AEM的 `P` 只使用成功样本保持相似边界。所有场景均失败时 `P_lite=0`。

### 4.2 有重复运行耗时时

若非AEM材料仍提供多次可核对的成功运行耗时，可以使用：

```text
P_lite = 参考成功耗时 / 成功运行耗时中位数
```

参考成功耗时应来自冻结基线或同一环境的最短稳定路径。报告必须写明效率依据是“操作量”还是“耗时”，不得在同一任务中混合。

## 5. 20条准则质量 Q

完整准则与权重见 `task-criteria-20.md`。

判断值：

```text
pass = 1
partial_pass = 0.5
fail = 0
```

`not_applicable` 排除，`insufficient_evidence` 不进入质量分，但计入覆盖分母。

同一准则命中多个步骤时，任务级判断取最差的适用实例：

```text
fail < partial_pass < pass
```

质量分：

```text
Q = Σ(准则重要性 w_i × 判断值 r_i) / Σ(w_i)
```

准则覆盖：

```text
C_criteria = 已判断适用准则权重 / 全部适用或证据不足准则权重
```

取最差实例只用于一次任务级计分；报告仍保留每个失败步骤，不能用聚合隐藏问题。

## 6. 原始简易任务分

```text
S_raw = 10 × (0.50 × E_lite + 0.20 × P_lite + 0.30 × Q)
```

权重含义：

- 50% 可完成性：任务首先必须能正确完成；
- 20% 路径效率：没有真实耗时数据时，动作量代理的不确定性较高，因此权重较低；
- 30% 准则质量：保留入口、信息、反馈、状态、结果和遮挡等20条标准的影响。

该权重是简易版内部算法，不是AEM官方公式。调整权重会改变版本，禁止在同一批评估中临时调权。

## 7. 覆盖与评级资格

同时检查 `C_scenario` 与 `C_criteria`：

- 两者都不低于 `0.85`：可以输出简易任务评级；
- 任一项在 `[0.70,0.85)`：输出“暂定简易任务评级”；
- 任一项低于 `0.70`：不输出数值和评级，标记“未评分”并列出补证项。

无论覆盖率如何，核心正常路径或成功真值未定义时均不得评级。

## 8. 风险上限

先计算 `S_raw`，再按问题风险限制：

- 存在一个影响核心任务的Gate：上限 `4.9`；
- 存在两个以上独立核心Gate，或错误结果可能造成不可逆、生产、权限、付费、隐私或外发损失：上限 `3.9`；
- 无Gate，但存在影响核心入口、必要信息、主要决策、结果或恢复的Major：上限 `5.9`；
- 否则无风险上限。

风险上限只限制最终分，不回写 `E_lite`、`P_lite` 或 `Q`。

“两个独立核心Gate”必须在问题合并后确认并通过 `task.independent_core_gate_count` 传入；不能把同一根因同时命中的多个准则或场景重复计数。

## 9. 证据上限

- `简易任务实测`：正常路径、至少一个边界和恢复场景实际执行后，无额外证据上限；
- `日志简易任务评估`：日志含完整状态、动作和结果真值时，上限 `8.9`；
- `方案级简易任务评估`：只验证设计意图，上限 `7.9`；
- `简易任务待验证`：不输出数值分。

最终分：

```text
S_final = min(S_raw, 风险上限, 证据上限)
```

没有某项上限时按10处理。报告必须同时显示原始分、触发的上限和最终分。

## 10. 评级

| 最终分 | 评级 |
|---|---|
| `[0,5)` | 差 |
| `[5,6)` | 中 |
| `[6,8)` | 优 |
| `[8,10]` | 卓越 |

评级描述简易任务质量，不代表真实用户完成率或线上发布结论。方案级结果最高只能为“优”。

## 11. 多任务汇总

默认分别展示每个任务的结果，再对已经评级的核心任务做等权平均：

```text
产品简易任务分 = Σ 单任务未舍入最终分 / 已评级任务数
```

若有核心任务未评分，产品结果必须标记“覆盖不完整”。用户明确提供业务权重时，可以补充自定义加权结果，但仍保留等权结果。

## 12. 计算输入结构

确定性脚本接收：

```json
{
  "assessment_type": "runtime",
  "task": {"name": "创建实例", "confirmed": true, "core_truth_defined": true},
  "scenarios": [
    {"id": "normal", "importance": 3, "judgment": "pass", "necessary_actions": 4, "observed_actions": 5},
    {"id": "invalid-input", "importance": 1, "judgment": "partial_pass", "necessary_actions": 2, "observed_actions": 3},
    {"id": "retry", "importance": 1, "judgment": "pass", "necessary_actions": 2, "observed_actions": 2}
  ],
  "criteria": [
    {"id": "F1.01", "importance": 3, "judgment": "pass", "affects_core": true},
    {"id": "F2.04", "importance": 2, "judgment": "partial_pass", "affects_core": false}
  ]
}
```

`assessment_type` 可为 `runtime`、`log`、`spec` 或 `unverified`。准则重要性必须来自 `task-criteria-20.md`，不能由输入任意覆盖；脚本会校验ID与权重。

`task.confirmed` 只能在用户确认任务链或用户预先明确免除确认时设为 `true`，不能由Agent自行推定。
