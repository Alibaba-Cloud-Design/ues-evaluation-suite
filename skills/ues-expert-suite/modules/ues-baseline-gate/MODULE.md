# 基础体验与风险检查

日常评估输出“发现问题 / 已检查范围未发现问题 / 尚无可判定结果”以及独立的验证完整性，不用一个“通过/不通过”否定整体产品体验。21条保留内容、稳定、任务保护、安全和透明度，不整体改成无障碍标准。此专项无分数，不参与UES加权。

## 联合运行接口

独立运行继续使用本专项现有合同。由 `ues-expert-suite` 编排时，读取总控提供的run ID、输入/画像/路由版本和共享 `evidence-index.json`；复用页面、状态、任务与原始证据ID，在本专项结果中保留每条BL判断自己的evidence说明。`units`和`evidence_refs`可以指向共享索引，但共享摘要不能替代21条及BL-04细项的正面验证。只写本专项产物和状态片段，由总控合并run-state；输入或证据版本变化时先标stale再复核。不得因此改变21条、结果合同或发布门禁规则。

同时读取已校验的 `diagnosis.json`。confirmed候选只作为检查线索，必须重新按本专项条目与结果合同判断；rejected候选用于避免重复误报，pending/blocked不得写成实证缺陷。已有证据满足条目要求时直接引用，只补风险与验证完整性缺口。

先读 [准则](references/canon-21.md)，再按 [结果合同](references/result-contract.md) 输出并运行 `node scripts/validate_baseline_result.mjs <result.json>`。旧技能名、文件名及BL-01～BL-21仅用于兼容；当前结果版本为0.3.0。

## 范围与证据

冻结产品、版本、角色、路由、任务、视口、时间、登录/数据/权限及授权边界。静态材料用static；可运行页面用runtime_page；能覆盖核心正常和适用异常/恢复任务用full_flow。按实际能力选择，不能为提高结果而缩小已承诺范围。

逐条判断：
- `pass`：声明子范围已正面验证，无已知违反；“没看到问题”不等于通过。
- `fail`：有可复现违反，关联证据和问题；轻微问题也保留，但不会自动成为发布阻断。
- `not_verified`：未测、证据/权限不足或超出范围。必须给具体原因；不并入失败。
- `N/A`：仅有正面证据表明业务条件不存在。不能用未测代替不适用。

合并项任一已知失败则fail，同时在`remaining_gaps`列出其余未验证要求；无失败但缺少适用子要求证据时not_verified。静态图不能证明运行行为，代码实现不能代替可达与有效证据。失败项保留原图、定位框、动作和结果；不可视觉定位的语义/日志问题不猜框。

运行页面覆盖主要页面、两个适用视口、内容压力、加载状态和可安全触达的错误/禁用/权限状态；存在主题能力时检查切换。full_flow补齐返回/重入、中断、错误预防、恢复重试及适用用户控制。受授权限制的终点如实记录，仍检查安全可达的确认与退出路径。未测清单不是测试通过。

## 问题与完整性分开

`findings_status`由已知失败决定，`verification_status`由当前范围未验证及remaining_gaps决定；两者可同时为issues_found和partial。展示实际影响和原专项严重度，不能把所有基础问题默认提到P1。跨专项同一根因合并、保留全部来源，不重复计问题数。

BL-04内含无障碍检查。检查时读取[无障碍细项](references/accessibility-checklist.md)，保留键盘、焦点、语义、对比和反馈等细项的证据与缺口。细项不是新的顶层准则，不单独计分或设覆盖出分门槛，不要求另行运行专项。任一细项实证失败则BL-04为fail；没有失败但存在适用未验证要求则not_verified；仅全部适用要求有正面证据才pass。

## 发布门禁是可选用途

默认`release_gate.status=not_assessed`。只有用户或组织明确要求发布审查，且事前有责任人、版本、适用范围及明确阻断条目规则时，才按合同评估独立门禁。禁止评完后倒推规则；无规则或缺关键验证时不能宣称可发布。普通缺陷保留，不自动触发发布拒绝；发布安全风险仍明确披露。

## 展示与迁移

按 [可视化规范](references/visual-report.md) 展示21条完整记录、已验证符合/实证缺陷/范围内未验证/范围外/不适用数量、问题及覆盖限制。无障碍在BL-04内展开，不用综合分覆盖已知风险，也不把风险卡写成全站不合格。

历史0.1.0记录先保留不可变副本；fail保持fail，旧N/A按真实原因迁移。未经重新取证不把旧未测改成通过。旧二元结论只放历史记录，不带入新版日常标题。
