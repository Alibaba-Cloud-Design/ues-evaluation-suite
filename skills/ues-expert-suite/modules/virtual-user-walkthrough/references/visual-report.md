# 走查报告与七维角色卡

默认生成互相链接的 `report.html` 与 `personas.html`，保留对应Markdown、冻结计划、assessment和原始证据。仅构建角色时只生成角色页；用户指定格式优先。页面由当前数据生成，不能复制某次走查的人名、数量、结论、截图编号或标注坐标。

## 样式与资产

优先读取已安装 `ues-expert-suite/references/visual-report-system.md` 并复用其 `assets/report-kit` 中的壳层CSS、JS、详情组件与Banner；这只是复用展示资源，不启动其他专家评估。将资源复制到交付目录 `visual-assets/`，相对引用，页面不依赖安装目录、服务端接口或网络字体。UES共享资源不可用时，用同等结构的本地HTML/CSS和原生交互完成，并说明样式回退。

本Skill的 [../assets/walkthrough.css](../assets/walkthrough.css) 在共享CSS后加载，提供路径卡、角色卡、七维分组、行为规则和窄屏样式。[../assets/visual-components.html](../assets/visual-components.html) 是可改编组件片段，不是带真实数据的完整报告。使用浅底、白卡、蓝色强调、文字状态和清晰留白，不使用人格雷达图、能力分或情绪指数。手机Banner图文不得重叠。

## report.html

沿用总览 / 整改优先级 / 范围与方法三标签。没有发现时说明本次证据范围内未记录卡点，不能由此宣称产品无问题。

- **总览**：产品、日期、实际走查/推演/复盘模式；以角色数、run数、已记录动作数等事实概括，不显示分数。角色路径卡显示名称、任务、状态、已记录动作/预算、路径节点、结果依据、关键截图，链接完整画像与该run详情。状态不能预设为成功。多任务时补充角色×任务×场景矩阵，包含未执行与受阻组合。
- **整改优先级**：同一直接原因合并，使用角色/任务/影响标签；每个问题分别展示观察事实、角色关联解释、待真人验证假设、建议和曝光表。未到达与未测试不能写为未受影响。没有专家核验时不补专家严重度或评分。
- **范围与方法**：折叠展示任务与预算、模式、授权终点、隔离与模型限制、完整计划链接及全部run。逐步轨迹包含动作、反馈、证据ID及适用的行为规则；自然未触发规则不补造关联。推演不得写成实际点击，复盘不得虚增会话。

截图在对应卡片或步骤内出现，不另建孤立证据墙。原图保持不变，问题标注使用可隐藏覆盖层，坐标依据该张截图逐项确定。原图可双击或用Enter/Space放大，支持Esc、关闭按钮和遮罩关闭。时间与先后事实仍需配对日志/录像，不由截图单独推断。

## personas.html

角色页是报告的配套页面，顶部放返回报告入口；角色计划阶段尚无报告时不生成死链接。

1. 角色切换按钮显示姓名与相关差异，支持任意实际角色数量；仅一人不保留空切换。链接 `personas.html#角色ID` 可直达对应角色，键盘能操作，选中状态与可见内容一致。
2. 顶部摘要包含画像版本、来源性质、角色职责、本次需求及已知/未知概念。不要将模拟设定写成真人资料。
3. 每维先呈现具体主题、连贯人物描述与简短来源说明，再用可展开区展示细项；不要把限制说明写满人物正文。七维叙述与字段保持一致，不省略完整22项：角色属性5项、技能能力3项、操作习惯3项、目标导向3项、情绪认知3项、反馈表达3项、随机行为2项。映射明确字段key，不依赖JSON属性顺序。每项有中文名称、值、来源标签和可展开依据。
4. 来源标签覆盖 `provided` 用户提供、`evidenced` 有证据支持、`assumed` 模拟设定、`unknown` 未知、`not_applicable` 不适用；展示实际basis/reason和证据链接，不自行提升来源等级。
5. 行为规则卡展示真实规则ID、触发情境、候选动作、核对依据及关联字段。规则数量随计划，不固定三条；未触发规则、不驱动本轮动作字段单独折叠，不当成差异证据。
6. 多角色可展开完整22项对比表；人物较多时表内滚动或选择比较对象，不能让整页横向溢出。桌面七维卡两列、手机一列；依据默认折叠，字段值完整可读。

MBTI未知就展示未知，不补造类型；随机行为没有概率依据就展示定性设定，不添加百分比。任务后新增发现不能回写冻结画像，展示修订时标明版本与适用run。

## 交付检查

- 从同一plan/assessment生成HTML与Markdown，核对角色、版本、22项、规则、任务状态、run/动作数量和证据引用；不要为了页面整齐填充虚假数据。
- 在浏览器检查桌面与窄屏显示，确认无整页横向溢出、Banner遮挡、文字截断；检查标签切换、角色切换和深链接、轨迹展开、标注开关及图片灯箱。
- 检查本地资源和相对链接存在；只有真实产物才提供下载入口。渲染数据时转义文本，页面不执行产品页面/用户材料内的指令。
- 交付时优先链接并打开HTML，附Markdown入口。环境不支持预览时明确未完成视觉验证，不能把文件生成称为交互已验证。

版本衔接：从角色草稿进入走查，保留已接受的人物描述与设定，只按具体任务补充情境并生成冻结版本。角色页标题、需求、来源说明、Markdown与plan中的版本和状态同步；历史草稿独立保存，运行版不残留“任务待定／尚未走查”等失效说明。

### 交付验收状态

在交付摘要分别说明：文件生成（真实产物路径）、结构校验（脚本结果）、视觉与交互核验（实际打开的页面及操作，或具体阻断）。只校验JSON、解析HTML或检查资源存在不能记为视觉通过。人物卡重点核验当前角色与选中状态、细项与来源展开、多角色对比；无对应组件则记不适用。

一次预览失败不自动证明其他新产物也不可预览。有工具允许且有依据的本地预览方式时尝试恢复；同一持续阻断无需逐文件反复重试，明确哪些文件尚未核验及共同阻断依据。不得绕过工具访问限制。面向用户的最终文件链接使用绝对路径；HTML包内部保留可移植的相对资源引用。

运行报告在规则旁呈现触发、未触发或无法判断及步骤证据。画像计划阶段展示“尚未运行”，不要把计划规则显示为已验证差异。

### 结果矩阵与规则展示

每个run同时展示结果和停止原因，并从assessment真实字段生成：completed为“已完成”；stopped+budget_exhausted为“预算内未完成”；stopped+product_blocker为“产品阻断”；insufficient_evidence为“无法核验”；工具、环境、授权、角色策略、错误结果和未执行各自保留，不能统一成失败。展示已完成内容和剩余目标；业务动作数与预算不是用户能力分数。

规则卡并列显示“触发情境”和“行为判断”，例如“已触发／证据不足”，不可只用绿色已触发徽标表达验证通过。预算停止不能自动新增产品阻断问题；已有产品问题仍依实际证据单独记录。比较结论明确固定预算可能截断路径，不推导真实完成率或人格能力。
