# 差异报告与专家交接

## 报告结构

1. 范围：产品版本、输入/运行模式、真实执行数量、推演数量、原始复盘会话数、已覆盖任务、隔离限制。
2. 用户群：每个画像的七维22细项角色卡、事实/假设/未知来源、本次情境、实际触发规则与有效差异。简短报告可展示摘要并链接完整画像和执行前plan.json，不能事后补造画像。未触发规则和不驱动本轮操作的字段不当成差异证据。
3. 任务矩阵：每个角色—任务—场景的完成/错误/停止/受阻/未执行；操作数有原始记录才展示，不能当人类耗时。
4. 关键问题：先写可核对的事实与影响，再写画像解释和待真人验证的假设。
5. 未覆盖与下一步：未走到的位置、授权终点、工具阻断、画像偏离及需要真实用户检验的判断。

默认以 `report.html` 展示结果、以 `personas.html` 展示完整画像，Markdown作为可移植文本版本保留；页面结构与组件见 [visual-report.md](visual-report.md)。每条证据化发现应在正文或交互式详情中显示对应截图、证据ID和一句截图解读；点击切换问题时三者同步切换。默认先展示红框标注视图，并提供“显示/隐藏标注”或“标注图/原图”切换。红框使用醒目但不过度遮挡的描边，编号与issue卡片一致；同一问题的多个区域用A/B后缀。原始截图必须可访问且保持未改动，标注层只承担定位作用，不产生新的事实。截图可复用，但每个issue要有自己的标注位置，不能只给通用截图。若动态事实还依赖日志、时间戳或录像，在截图旁明确列出配对证据与静态截图的证明边界。可视化只呈现已有计划和记录，不能为了图表补造或重算数字。默认不创建空看板或模拟访谈实录。

## 如何表达共性和特定角色障碍

“共性”只表示本次多个被观察角色/会话在同一位置出现相同现象；“特定”只表示目前在某角色运行中观察到，不代表其他人群不会遇到。

每个问题有曝光表：`encountered` 已遇到问题、`reached_without_observed_issue` 到达同状态但未观察到问题、`not_reached` 未到达、`not_tested` 未测。后三者不能笼统写成“不受影响”。

只有任务、版本、状态、权限和初始条件可比时才解释画像差异。没有控制条件时，不因A完成而B停止就归因为知识、性格或技能。可给出待验证解释。

同一角色重复运行不增加画像数。replay的同一source_session_id不增加原始样本数。不要计算统计显著性或人群百分比；需要正式实验时转到方法验证参考。

## 三层证据与根因合并

- 事实：实际页面文案、动作、反馈或原日志中的结果。
- 解释：事实与七维规则的关联；标明是否存在画像偏离或混杂因素。
- 假设：对真实用户的影响与预期修复收益；未经真人或独立实验验证不当确定事实。

同一直接原因、同一对象/可比组件、同一用户后果、可由同一修改解决时可合并，保留所有run/step/evidence引用。不同原因、业务后果或需独立修复时不要仅因标题相似而合并。原因未知时保留候选分组，不自行确认为同根因。

本Skill用任务影响标签 `blocks_goal`、`wrong_result`、`extra_effort`、`uncertainty`、`risk_exposure` 帮助排序，不冒充专家已判Gate/Major。不因只有一个角色受影响而降低潜在严重风险。

## 对接现有Skill

适用且在当前请求范围内时才调用；可用性通过目标环境实际发现，不硬编码本机路径。没有对应Skill可继续完成走查及交接包。

| 可用专家 | 交接内容 | 不可做的事 |
|---|---|---|
| `usability-suite-47` 易用性 | 入口、理解、决策、反馈、恢复的状态和轨迹 | 因虚拟用户通过，就默认47条准则全部通过 |
| `consistency-suite-22` 一致性 | 可比页面/控件/状态、命名或行为差异及基准来源 | 只有一次操作就声称跨页一致性缺陷 |
| `task-experience-score` 任务分 | 任务合同、真值证据、场景与实际动作记录 | 将模拟人数比例代入AEM；绕过任务确认门 |
| 其他当前可用专家 | 本次实际采集且与其准则相关的证据 | 猜测准则ID、分数或未运行的专家结论 |

交接包含issue ID、任务、run/step、原始证据、可观察事实、解释、假设、影响、局限和建议核查主题。未读取目标canon前只给自然语言主题，不填正式准则ID。

专家可发现画像无关的其他问题，分开标来源。发现“不一致”也不能只靠用户说不一致，仍需建立可比实例。专家Skill可能需要补测；新增操作属于专家核验，不追溯成虚拟用户原始路径。

联合报告以统一问题ID联结各专家判断和原始发现；各专家内部沿用自己的去重和计分法。不跨Skill盲目相加扣分、平均异构分数或改变权重。目标任务分规则不接受当前材料时，保留交接待办，不强行转换。

## 输出措辞示例

合适：截图显示选项名称但未展示解释；这构成知识较少角色的理解风险假设，点击后的帮助能力未验证。

不合适：虚拟用户点击后没有帮助、因此放弃了任务（实际只给了一张截图）。
