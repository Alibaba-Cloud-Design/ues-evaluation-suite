# 页面性能评分专家

以 PCP（Perceivable Contentful Paint）度量控制台主要界面可感知的时间，以产品阶段、数据来源和统计口径约束结论。线上、页面 reporter 与预上线合成测量必须分开命名和展示。

## 联合运行接口

独立运行继续使用本专项现有合同。由 `ues-expert-suite` 编排时，读取总控的输入/画像/路由版本与共享 `evidence-index.json`；把导航锚点、最后未完成帧、首个合格帧、稳定确认帧、filmstrip及指标记录登记为共享证据，但 `performance-capture.json` 仍是计时状态、完成条件、误差和分数的权威产物。共享截图或DOM摘要不能倒推PCP或完成时刻。新采样遵守导航前armed顺序，产物终结后只回写本专项状态片段，由总控原子更新run-state、综合分与报告。输入、路由或完成条件变化时先标stale，不改变PCP或简易性能公式。

## 必读口径

任何计分前完整读取 [references/scoring-model.md](references/scoring-model.md)，它是PCP模式的计分依据；简易网页性能模式以 [references/simple-web-performance.md](references/simple-web-performance.md) 为计分与测量依据，两者不混用指标名称。

需要从预上线或已上线 URL 读取/测量 PCP、判断页面是否已接入 reporter，或制定数据接入方案时，再完整读取 [references/pcp-measurement.md](references/pcp-measurement.md)。

## 适用阶段

- **概念、线框、视觉稿、交互原型和未形成稳定部署的开发阶段**：性能维度记 `not_applicable`，不计 0 分，也不进入易用性分。此时资源、网络、构建方式和运行环境尚不具备可比性。
- **预上线、灰度、UAT、生产仿真或已上线阶段**：性能维度适用。必须能通过 URL 访问可运行页面，并明确环境和路由。
- 阶段名称不清时，根据是否存在稳定部署、接近生产的构建产物和可重复访问 URL 判断；无法确认则标记“阶段待确认”，不强行计分。

## 工作模式

选择一种主模式，可在同一报告中并列其他模式，但不要混用结论名称。

1. **正式线上评分**：已有 Stonehenge、组织性能平台、数据接口或用户提供的 PCP 聚合值，且能说明产品/路由、环境、统计窗口和聚合方式。
2. **Reporter 单次实测**：页面暴露 `window.ALIYUN_CONSOLE_PERFORMANCE_REPORTER.getPCP`，读取当前导航的 PCP。可换算单次实测分，不得称为线上聚合分。
3. **预上线合成 PCP**：页面已达到预上线阶段，但未接入 Stonehenge/reporter。用受控导航和可复核的“主要界面已渲染”判定测得合成 PCP，并使用同一公式评分；必须在名称中保留“预上线合成”。
4. **简易网页性能回退**：预上线或线上网页没有合法PCP、PCP不适用，或预上线合成PCP合同不能满足时，自动读取简易回退合同并尝试一次受控首屏测量；不因PCP读取受阻直接结束。
5. **无法评分**：PCP路径和简易回退均不可用时，页面虽已达到预上线阶段，但无法稳定访问、无法在导航前开始计时、无法定义或核对主要界面完成状态。列出阻断，不输出猜测分。
6. **补充性能诊断**：可记录 FCP、LCP、TTFB、加载资源或任务交互时延来解释问题，但这些值不直接进入 PCP 公式。

## 数据源优先级

1. 组织性能平台或官方数据接口已产出的 PCP 聚合值。
2. 用户提供的可审计导出，包含指标、单位、窗口、聚合口径和对象。
3. 当前页面 `getPCP` 返回的单次值。
4. 预上线环境中按本 Skill 规则测得的合成 PCP。
5. 按独立合同采集的 visible_first_view_ms，用于简易性能分，不是PCP。
6. FCP/LCP/load等通用指标仅作补充诊断，不直接替代上述两种计分指标。

不因为已拿到单次 PCP 就停止寻找用户明确要求的线上聚合数据。不在未得到组织口径时自行把原始样本算成“官方 PCP”。

## 授权会话能力预检

对已登录业务页先读取 [references/session-capture.md](references/session-capture.md)，区分目标定位、真实页面执行环境与连续采集能力。能访问页面不等于能计时；独立采集器不默认继承登录态。有已授权且可用的恢复方式就继续执行；实际能力受限时记录检查依据及尚未验证项，不以重复刷新代替修复。

## 自动回退的范围

对可运行网页的性能评估，先核验合法PCP；没有可用PCP时，继续检查简易网页性能的导航前采集能力并执行适用回退，无需等待用户再次提出。Reporter在受限脚本环境中返回undefined不证明真实页面未接入；区分来源不可读与不存在，仍可继续简易路径。只在两条路径均受阻时给出整体未评分，分别记录原因，不计0分。

尊重明确“只检查已有记录／只核验PCP／不导航／不新采样”等限制，此时不扩展采样。禁止将LCP冒充PCP、禁止预上线合成PCP，不等于禁止独立命名的简易首屏测量；用户明确禁止所有替代测量时遵从。已取得合法结果后不默认额外测量；单项调用不自动运行其他专项。

## 已有记录读取受阻

用户要求检查已有记录时，入口不可读不等于记录缺少PCP。先检查同一记录的页面可见文本、已提供附件或已授权数据入口；只尝试有依据且工具允许的替代来源，不循环重试同一失败入口或绕过访问限制。保留原入口、错误、实际读取位置、原始字段及同一记录的对应依据。来源无法对应时不拼接字段、不将替代数据冒充原记录。

没有可读替代来源时标记“记录读取受阻，指标资格未判定”，列出所缺材料；可继续不受影响的其他记录。不要为完成已有记录检查而新采样，也不用当前页面的load、LCP等补造原记录PCP。来源可读后仍按原评分合同判断资格，不降低门槛。

## 导航前取证（新采样必经）

采集合成 PCP 或简易网页性能前完整读取 [references/performance-capture-preflight.md](references/performance-capture-preflight.md)，在首轮正式导航前完成能力预检、冻结条件、启动采集并取得armed确认，导航后立即验收样本，保留 `performance-capture.json`。仅能在加载后取截图时，提前说明blocked；执行漏采但具备能力时，依该合同在安全只读范围补采一次，不直接跳过。已有聚合或reporter数据按其来源合同读取，不要求重复导航。

## PCP评分流程（简易回退按其独立合同执行）

1. **冻结测量合同**：记录产品、路由/页面、环境、用户群、统计窗口、聚合方式、样本数和单位。
2. **验证指标**：只接受 PCP 毫秒值进公式。P50/中位数、P75 和算术平均数是不同口径，不得互称或混合。
3. **标记结果类型**：选择“正式线上性能分”、“Reporter 单次实测性能分”、“预上线合成 PCP 性能分”、“性能未评分”或“不适用”。
4. **执行计算**：优先运行 `node scripts/calculate_performance_score.mjs --pcp-ms <value>`。保留全精度中间值，展示时四舍五入到一位小数。
5. **复核边界**：检查 1000ms、1500ms 和 5500ms 的分段边界；检查输入是否为非负有限数。
6. **形成报告**：展示 PCP 值、分数、评级、数据源、统计口径、样本与局限，不只报一个分数。

预上线合成 PCP 的完成状态定义、单次测量和证据要求见 [references/pcp-measurement.md](references/pcp-measurement.md)。不能证明首个合格渲染时刻时，不得因为页面最终看起来完整就倒推 PCP。

### 命令示例

```bash
node scripts/calculate_performance_score.mjs \
  --pcp-ms 2800 \
  --source Stonehenge \
  --result-type field_aggregate \
  --aggregation P75 \
  --window "2026-08-24/2026-08-30" \
  --sample-count 2500
```

批量输入为 JSON 数组，每项至少包含 `pcp_ms`：

```json
[
  {"name": "概览页", "pcp_ms": 1280},
  {"name": "实例列表", "pcp_ms": 2800}
]
```

运行 `node scripts/calculate_performance_score.mjs --input-json <path>`。批量结果默认不生成产品平均分；除非用户提供了官方路由权重或聚合方法，不自行发明产品级口径。

预上线合成 PCP 默认只执行一次受控导航。取得毫秒值后运行：

```bash
node scripts/calculate_performance_score.mjs \
  --pcp-ms 2520 \
  --source synthetic_filmstrip \
  --result-type synthetic_lab \
  --environment pre-release \
  --aggregation single \
  --sample-count 1
```

报告必须标记“单次测量，波动未知”。只有用户明确要求复测、对比或建立基准时，才使用脚本的 `--runs-json` 能力进行多次测量。

## 与易用性和任务分协同

- 使用平台/reporter 时，在易用性 URL 实测的首次导航中读数，不为了性能卡片默认额外刷新页面。
- 预上线合成 PCP 需要在导航前启动采集并完成一次受控测量，因此应作为单独的性能步骤执行，不把易用性过程中已经加载完成的页面反推为 PCP。
- 易用性中“操作到首次可见反馈”仍按交互反馈评估；PCP 只表示首屏主要界面感知时间。
- PCP 不进入任务分的 `E` / `P` 公式，也不因为任务分偏低而再扣分。
- 同一慢加载可以同时是易用性证据和性能数据，但联合报告必须保留各自的分数来源，不重复构造一个综合扣分。

## 输出结构

1. **结论**：PCP路径与简易路径各自状态；最终指标为`PCP ms`或`visible_first_view_ms`、`S / 10`及评级，或两条路径的未评分原因。简易结果必须标明“简易性能分，非PCP，单次可识别首屏”。
2. **测量合同**：产品、路由、环境、窗口、聚合方式、样本数和单位。
3. **数据来源**：平台/API/导出/页面 reporter/预上线合成测量；记录获取时间和原始字段摘要。
4. **计算链**：显示所在分段、代入公式、未四舍五入值和展示分。
5. **诊断指标**：如已采集，单列 FCP/LCP/TTFB/交互时延，不进入 PCP 分。
6. **数据质量与限制**：样本、采样间隔、判定规则、截图证据、权限、缓存、网络、统计口径和未验证项。
7. **下一步**：只给与证据对应的接入、采样或优化动作。

### 截图证据呈现

- 合成PCP的首个合格帧、前一帧和可视性能问题均保留未改动原图；报告默认在衍生视图中用红框与证据／问题编号标出完成条件区域、迟到内容或失败区域，并允许隐藏标注或查看原图。
- 同一结论涉及多个区域时使用同号A/B后缀；前后帧使用一致的区域与尺度，避免框选变化本身制造差异。
- 标注只用于定位，不改变帧内容、不遮挡关键状态，也不能证明持续时间。PCP时刻与稳定时长仍以时间戳、filmstrip或测量记录为准。
- 无法可靠定位到可见区域、或问题只存在于聚合指标和资源日志中时，不画猜测框；改为提供可复核的数值、网络或日志证据。

生成可视化报告时读取 [references/visual-report.md](references/visual-report.md)。使用 UES 统一三标签壳层、性能电影条、问题卡和证据灯箱。合成或单次PCP在报告界面中显示为“简易性能分”，同时保留“预上线合成 PCP”或“Reporter 单次实测”等数据来源；正式监控聚合值显示为“正式线上性能分”。

## 边界

- PCP 是阿里云控制台特化的首屏感知指标，不默认适用于所有网站。
- 不用骨架屏出现、FCP、LCP、DOMContentLoaded 或 `load` 时间直接冒充 PCP。合成测量必须根据预先声明的主要界面完成状态判定。
- 合成 PCP 是实验室近似值，不得标为 Stonehenge PCP、正式线上分或真实用户分布。
- 不把 P75 称为中位数，不把平均值称为分位数。
- 不为取数擅自修改线上页面、采样率、埋点、环境变量或上报逻辑。
- 不提交、删除、发布、付费、变更权限或执行其他高风险任务来制造性能样本，除非用户另行明确授权。
- 不代替容量、压测、后端性能、稳定性、可用性或性能安全审计。

### 看板式报告呈现

HTML 报告默认采用 UES 看板布局：浅灰背景、白色横向卡片、左侧大分数与分段标尺、右侧结论及关键指标，下接可筛选明细。保留总览、整改优先级、范围与方法的内容层级。完整读取本技能的 `references/dashboard-report.md`，复制本技能的 `assets/report-kit/`；单独安装本专项时也能生成同样外观。现行评估规则与计分不变。

报告固定使用浅色模式，不随系统主题切换；页头采用蓝色渐变、扇形报告卡、悬浮圆环和底部波浪，复用 `assets/report-kit/ues-banner-art.png`。装饰图不承载实际分数。

首页参考布局：综合分与趋势区旁独立放子指标概览；易用性、任务、一致性为白色横卡，底部较小模块双列。综合分区域按分数档位使用浅色渐变，普通专项分数区保持白色，不统一染绿。Banner直接使用用户提供的PNG原图，通过CSS定位适配透明留白，不重绘。
